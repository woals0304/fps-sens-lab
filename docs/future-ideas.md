# 향후 확장 아이디어

## 1. 더 정교한 시험 규약

- 표적 크기 프리셋 추가
- 추적 표적 속도 프리셋 추가
- 영웅 분류별 기본 시험 규약 분리
- 피로도에 따라 짧은 규약 / 긴 규약 선택

## 2. Bayesian optimization 확장

- 현재 자동 측정 점수를 목적 함수처럼 사용
- 다음 감도를 `탐색 + 활용` 균형으로 고르기
- 지금은 규칙 기반 후보 압축을 쓰지만, 나중에는 Gaussian Process 기반 다음 감도 제안기로 교체 가능
- 최종 검증 단계는 그대로 두고, “다음에 무엇을 시험할지”만 Bayesian 방식으로 바꾸는 구조가 적합

## 3. Bandit 확장

- 감도 후보를 arm처럼 다루기
- 비교 시험 승패와 자동 측정 종합 점수를 보상으로 사용
- Thompson Sampling 또는 UCB로 다음 비교 쌍 자동 선택
- 반복 비교를 줄이고, 애매한 구간만 더 자주 시험하는 방향으로 확장 가능

## 4. 영웅별 감도 추천

- Soldier / Cassidy / Widowmaker / Tracer 같은 영웅별 시험 묶음 만들기
- 즉발 사격형, 지속 추적형, 투사체형, 고기동형 별로 다른 기본 규약 제공
- 영웅 전환 시 자주 쓰는 감도 세트를 저장

## 5. 개인 히스토리 기반 추천

- 최근 세션 가중치를 더 높이기
- 컨디션이 좋은 날 / 피곤한 날을 구분해서 감도 패턴 저장
- 플레이 성향과 영웅 분류 조합별 안정 범위 따로 저장

## 6. PyTorch 보조 모델 확장

원칙:

- 딥러닝이 들어가더라도 `Python + PyTorch`만 사용
- 규칙 기반 추천을 지우지 않고 보조 기능으로만 사용

추가로 모으면 좋은 데이터:

- 감도별 자동 측정 raw metric 전체
- 감도별 가중 종합 점수
- 단계별 통과 / 탈락 기록
- 최종 검증 통과 여부
- 최종 확정 감도
- 수동 체감 점수와 메모
- 영웅 분류 / 플레이 성향 / DPI
- 반복 세션 간 감도 이동 방향

가능한 보조 출력:

- `predicted_best_sensitivity`
- `recommended_next_pair`
- `predicted_stable_range`

## 7. 나중에 딥러닝을 붙이려면 어떤 데이터를 모아야 하나

최소 단위는 “감도 1개를 어떤 규약으로 시험했고 어떤 결과가 나왔는가”입니다.

추천 컬럼:

- DPI
- 감도
- 영웅 분류
- 플레이 성향
- 시험 규약 버전
- 순간 조준 raw metric
- 추적 조준 raw metric
- 회전 반응 raw metric
- 자동 가중 종합 점수
- 수동 범위 시험 점수
- 후보 압축 단계 결과
- 최종 검증 결과
- 최종 채택 감도

## 8. 안전한 데이터 수집 범위

가능:

- 브라우저 실험실에서 얻은 자동 지표
- 사용자가 직접 적은 점수와 메모
- 사용자가 입력한 영웅 분류와 감도 범위
- 브라우저 안의 테스트 시드와 시험 규약 정보

금지:

- 게임 메모리 읽기
- 패킷 변조
- 후킹
- 외부 게임 자동 수집
