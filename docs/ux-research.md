# 입력 UX 개선 근거 (2026-09-28)

## 참고한 원문
- W3C WAI, Validating Input: https://www.w3.org/WAI/tutorials/forms/validation/
- W3C WAI, User Notifications: https://www.w3.org/WAI/tutorials/forms/notifications/

입력 요구사항을 설명하고, 잘못된 값을 수정할 수 있도록 구체적인 오류를 제공한다는 접근성 지침을 적용했다. 이 자료는 제품의 전환율 개선을 입증한 실험 결과가 아니다.

## 확인한 코드 문제와 변경
- 감도를 매 키 입력마다 포맷해 편집 중 소수점과 빈 문자열을 유지할 수 없었다. 화면 입력 문자열을 수치 설정과 분리했다.
- 시작 버튼 비활성화와 공통 오류만으로는 어떤 값을 고쳐야 할지 파악하기 어려웠다. 폼 제출 시 첫 오류로 초점을 옮기고 필드별 설명과 오류를 aria-describedby로 연결했다.
- 입력을 시작하기 전에는 오류를 표시하지 않는다. 필드 이탈 또는 제출 후에 표시한다.
- 키보드 Enter로 제출할 수 있는 표준 form을 사용한다.
- 각 설정의 확인 위치와 허용 범위를 입력 옆에 안내한다.
- 추천값이 없는 저장 기록에는 진행 중인 테스트라고 표시한다.

## 검증 범위
React DOM 테스트로 빈 값 편집, 소수점 유지, 잘못된 제출 차단, 오류 초점과 연결, 수정 후 제출을 확인한다. 클라우드 브라우저에서 관리형 미리보기 접근이 ERR_BLOCKED_BY_CLIENT로 차단되어 스크린샷 기반 시각 점검은 완료하지 못했다. 실제 사용자 사용성 테스트, 스크린리더 실기 검증, 모바일 시각 검증, 전환율 측정은 아직 수행하지 않았다.
